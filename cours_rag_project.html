Leçon complète : RAG avec FAISS, LangChain et OpenAI

1) Objectif du projet

Ce projet permet de :

  • lire des fichiers texte dans le dossier docs/
  • les découper en morceaux
  • créer des embeddings avec OpenAI
  • stocker les vecteurs dans une base locale
  • retrouver les meilleurs documents à partir d’une question

Cela s’appelle un système RAG (Retrieval Augmented Generation).

2) Ce que fait le projet dans la vraie vie

Le projet lit des textes sur des entreprises comme Google, Microsoft, Nvidia, SpaceX et Tesla.

Ensuite, on pose une question comme :

What was NVIDIA's first graphics accelerator called?

Le système cherche les morceaux les plus proches de cette question et retourne les passages les plus pertinents.

3) Les fichiers du projet

3.1 ingestion_pipeline.py

Il construit la base de connaissances.

  • vérifie le dossier docs/
  • charge les fichiers .txt
  • lit en UTF-8
  • coupe les textes en morceaux
  • crée les embeddings
  • sauvegarde la base vectorielle

3.2 retrieval_pipeline.py

Il répond aux questions.

  • charge la base FAISS
  • crée un retriever
  • envoie la question
  • récupère les meilleurs passages
  • affiche le contexte

3.3 docs/

Le dossier contenant les documents sources.

4) Les technologies importantes

4.1 Python

Langage principal pour lire, traiter et appeler les APIs.

4.2 LangChain

Outil permettant de :

  • charger les documents
  • les couper
  • gérer les embeddings
  • travailler avec la base vectorielle

4.3 OpenAI Embeddings

Les embeddings sont des représentations numériques du texte. Deux phrases proches sémantiquement auront des vecteurs proches.

4.4 FAISS

FAISS est une base vectorielle locale. Elle permet de stocker des embeddings et de retrouver rapidement les morceaux les plus proches d’une question.

5) Qu’est-ce qu’un RAG ?

RAG = Retrieval Augmented Generation.

Le principe :

  1. on pose une question
  2. on cherche les meilleurs passages dans la base documentaire
  3. on donne ces passages au modèle
  4. le modèle répond avec un contexte pertinent

6) Problèmes rencontrés et solutions

6.1 Erreur UnicodeDecodeError

Ca arrivait parce que les fichiers texte étaient lus avec le mauvais encodage système Windows.

loader_kwargs={"encoding": "utf-8", "autodetect_encoding": True}

Cette ligne force Python à lire les fichiers en UTF-8, ce qui évite les caractères cassés.

6.2 Base vide ou incomplète

Le dossier db/ pouvait exister sans contenir un vrai index.

Solution :

os.path.exists(os.path.join(persistent_directory, "index.faiss"))

On vérifie l’existence du vrai index FAISS, pas seulement du dossier.

6.3 Chroma crashait sur Windows

Le projet a d’abord utilisé Chroma, mais cette base a provoqué des problèmes sur Windows.

La solution a été de passer sur FAISS, qui est plus stable et plus simple pour le développement local.

7) Explication de ingestion_pipeline.py

7.1 Importations

import os
from langchain_community.document_loaders import TextLoader, DirectoryLoader
from langchain_text_splitters import CharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import FAISS
from dotenv import load_dotenv

Chaque import a un rôle précis :

  • os : gestion des chemins et dossiers
  • DirectoryLoader : lecture de plusieurs fichiers
  • TextLoader : lecture d’un fichier texte
  • CharacterTextSplitter : découpage des textes
  • OpenAIEmbeddings : création des vecteurs
  • FAISS : stockage vectoriel
  • load_dotenv : lecture des variables secrètes

7.2 load_dotenv()

load_dotenv()

Cela charge la clé OpenAI depuis le fichier .env.

7.3 load_documents()

loader = DirectoryLoader(
    path=docs_path,
    glob="*.txt",
    loader_cls=TextLoader,
    loader_kwargs={"encoding": "utf-8", "autodetect_encoding": True}
)

On lit uniquement les fichiers texte dans docs/, avec un encodage explicite et correct.

7.4 split_documents()

text_splitter = CharacterTextSplitter(chunk_size=1000, chunk_overlap=0)

On découpe le texte en morceaux plus petits pour améliorer la recherche et la qualité des vecteurs.

7.5 create_vector_store()

embedding_model = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = FAISS.from_documents(documents=chunks, embedding=embedding_model)

Chaque chunk est transformé en embedding puis ajouté à la base vectorielle FAISS.

7.6 main()

Cette fonction est le point d’entrée du système.

if os.path.exists(os.path.join(persistent_directory, "index.faiss")):
    ...
else:
    ...

Elle vérifie si la base existe déjà avant de la recréer.

8) Explication de retrieval_pipeline.py

8.1 Chargement du modèle d’embedding

embedding_model = OpenAIEmbeddings(model="text-embedding-3-small")

Le même modèle doit être utilisé pour la recherche que pour l’indexation.

8.2 Vérification de la base

if not os.path.exists(os.path.join(persistent_directory, "index.faiss")):
    raise ValueError(...)

Le script vérifie que la base est bien présente avant de la charger.

8.3 Chargement de la base FAISS

db = FAISS.load_local(persistent_directory, embedding_model, allow_dangerous_deserialization=True)

Cette ligne ouvre la base sur disque et permet de l’utiliser pour la recherche.

8.4 Question utilisateur

query = "What was NVIDIA's first graphics accelerator called?"

La méthode transforme la requête en vecteur, puis la compare avec les documents indexés.

8.5 Retriever

retriever = db.as_retriever(search_kwargs={"k": 5})

k = 5 signifie : “renvoie les 5 meilleurs résultats les plus proches”.

8.6 Affichage des résultats

relevant_docs = retriever.invoke(query)
for i, doc in enumerate(relevant_docs, 1):
    print(f"Document {i}:\n{doc.page_content}\n")

On affiche le contexte retourné pour que l’utilisateur puisse voir d’où provient la réponse.

9) Ce qu’on a appris

  • Les fichiers texte doivent être lus avec le bon encodage.
  • Une base vectorielle ne fonctionne pas si l’index n’est pas bien vérifié.
  • Le backend vectoriel peut être la vraie cause des erreurs.
  • Le même modèle d’embedding doit être utilisé de manière cohérente.
  • FAISS est un bon choix pour un projet local stable.

10) Vision d’ensemble

fichiers .txt -> lecture -> découpage -> embeddings -> FAISS -> recherche -> contexte -> réponse

11) Ce qu’il faut retenir

  • ingestion_pipeline.py = construit la mémoire
  • retrieval_pipeline.py = cherche dans la mémoire
  • docs/ = source documentaire
  • FAISS = moteur vectoriel de recherche
  • OpenAIEmbeddings = transforme le texte en vecteurs

12) Conclusion

Ce projet est une mini architecture RAG complète. Il montre la logique : lire des documents, les indexer, les comparer à une question et retrouver les meilleurs passages.

Le système fonctionne maintenant car les erreurs d’encodage, de base de données et de backend ont été corrigées.
